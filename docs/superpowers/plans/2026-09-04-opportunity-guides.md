# Opportunity guide publication

The request authorizes writing and publishing useful guides, with 5–10 relevant articles for each of the 11 records in mailer_web/database/seeders/data/opportunities.json. The CMS is landing_cms (the supplied landing/_cms path does not exist).

## Editorial design

Expand the existing 50-guide library with 32 distinct guides. Count existing guides only against directly relevant seed topics; retain all existing URLs. Use five guides per opportunity as the minimum, rather than padding every category to ten. Include the two Later opportunities as educational coverage without claiming that a planned product is available.

Every new guide has a direct answer, a concrete reader scenario, specific steps, an original example or worksheet, a completion check, and a realistic Venmail action. Explain free software versus hosted sending costs. Do not invent free API quotas, native Shopify connectors, automated warm-up, white-label entitlements, or a free lead database. Verify technical recommendations against primary documentation and public repositories. Use the site's existing author convention without adding visible reviewer claims.

## Execution

1. Record explicit seed-to-slug coverage and add a regression check for the 5–10 requirement.
2. Write 32 guides: deliverability 1, warm-up 4, SMB marketing 5, signup verification 5, commerce 3, WordPress 2, agencies 2, React 5, lead research 5. Improve relevant existing guides with concrete free utilities.
3. Register content and primary sources using the existing structured block renderer. Preserve measured keyword metrics. Make counts dynamic and broaden blog/feed wording to the expanded library.
4. Validate coverage, duplicates, sources, routes, feeds, article rendering, and the static production build. Review a desktop and mobile article.
5. Commit only this work, publish via the existing main-branch CI/CD, and verify live article content, sitemap, RSS, and category coverage. Do not touch production mail containers.
